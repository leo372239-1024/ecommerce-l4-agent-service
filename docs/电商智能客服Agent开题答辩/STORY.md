## 二、核心论证主线（一句话）

> 电商售后的高风险写操作（退款、取消）缺少「身份—证据—授权—审批—幂等—回执」的可验证闭环；
> 本课题拟以中文单 Agent 全栈系统为对象，用**可验证规划、受权工具路由、时效记忆、证据反思与恢复**四项机制补上这一工程断层，并以冻结模拟评测逐项量化验证。

## 三、叙事节奏（四段式 · 开题逻辑）

1. **为什么立这个题（P03–P04）**：行业规模与需求增长 → 工程能力断层（不是产品空白）→ 立项必要性成立。
2. **要做什么、怎么想（P05）**：项目主题与三条核心想法（能回答→能办完 / 信任模型→信任证据 / 调用接口→受控事务）+ 差异化边界。
3. **打算怎么做（P06–P14）**：研究目标与内容 → 总体架构 → 执行闭环 → 技术选型与部署 → 四项关键技术 → 安全隔离。全篇重心（9 页，占 50%）。
4. **期望达到什么、怎么安排（P15–P17）**：预期效果与验收指标 → 可行性分析 → 实施计划与团队分工。

> 全篇时态以「拟 / 将 / 预期」为主；已有原型能力一律标注为**前期预研基础**，用于支撑可行性，不作为成果展示。

## 六、关键数据锚点

### 6.1 前期预研验证数据（用于支撑可行性与机制有效，标注为「预研」）

- 规划主集：P **159/180（88.33%）** vs B2 **117/180（65.00%）**，family 均衡差 **+9.14pp**，95% CI **[−4.66, +23.45]pp**（区间含 0）。
- 时效记忆：P **180/180（100%）** vs M-vector **62/180**（任务级 **34.44%**，family 均衡率 **24.36%**），family 均衡差 **+75.64pp**（= 100% − 24.36%，两口径不可互推），CI **[+55.13, +92.31]pp**；条件 Prompt Token **513,308 → 180,291（−64.88%）**。
- 失败恢复：P **144/144（100%）** vs A-reflect **48/144（33.33%）**，差 **+66.67pp**，CI **[+33.33, +100]pp**。
- 工具路由：1000 项目录、50 例 ×3 trial，两组均 **150/150（100%）**，差值 **0pp**（未达预登记 +5pp）。
- 连续运行：**7200.015 秒**、**120/120** 只读任务通过、0 失败、123 次模型调用、298,160 Token、服务容器内存峰值 **2.235 GiB**。
- 控制 API 压力：10 并发 **174.37 RPS / P95≈79ms**；50 并发 **158.75 RPS / P95≈563ms**，全 200。
- 工程验收：后端 **293 项**测试 + 前端 **5 项** SSE 测试 + TypeScript 构建；同宿主 Worker 接管约 **30.19 秒**，fencing 1→2，28 条事件连续。
- 规模：**40** 个真实 MCP 商家工具；**3762** 个冻结评测单元；知识库 **1024** 维向量。

### 6.2 预期目标（P15，向前看）

| 技术方向 | 预期目标 | 对照基线 | 预期提升 | 验收方式 |
|---|---|---|---|---|
| 可验证规划 | 复杂任务严格成功率 ≥ 85% | 原生 ReAct + 混合检索 | ≥ +8pp | 36 场景 × 5 trial，family 均衡差 |
| 受权工具路由 | 1000 项候选下质量不回退 | 混合检索路由 | ≥ 0pp（不劣化） | 50 例 × 3 trial，权限与参数校验 |
| 时效记忆与上下文 | 严格成功率 ≥ 90% | 最近对话 + 向量历史 | ≥ +50pp；Token 降 ≥ 50% | 长会话专项，配对 Token 口径 |
| 证据反思与故障恢复 | 可恢复故障成功率 ≥ 90% | 关闭反思基线 | ≥ +15pp | 故障族对照；永久故障安全停止单列 |

- 规模：**≥ 3000** 个冻结评测单元、**4** 项主指标、**4** 类对照基线；工程验收预期：后端测试全通过、**≥ 2 小时**连续运行。
- 验收原则：**终态 ≠ 成功**——需联合检查订单作用域、当前证据与写入回执；未达标项按预登记规则如实记录，不更换分母。

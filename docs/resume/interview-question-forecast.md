## 1. 十个最高概率提问

### Q1｜LangGraph 图结构与状态设计（编排细节）

你说用 LangGraph 做持久化执行——请具体讲一下这张图是怎么设计的：节点怎么划分、State 的 schema 怎么定、checkpoint 存在哪里、什么条件下会触发 interrupt，以及为什么用 interrupt 而不是用一个普通的状态标记加轮询？

### Q2｜编排框架选型判断

langchain-chain、langchain-agent、langgraph 这三种编排方式，你分别在什么业务场景下会选哪个？你自己项目里为什么最终选了 Graph 而不是 AgentExecutor？如果只是一个「读取参数 → 调接口 → 格式化输出」的固定流程，你还会上 LangGraph 吗？

### Q3｜Skill 封装业务流程的方法论

你项目里的 40 个工具，你是怎么从「商家业务接口」抽象成「Agent 可用 Skill」的？如果给你一条新业务流程——比如「电气设备巡检发现异常后走告警确认、工单派发、复检闭环」——你会按什么标准把它切成几个 Skill？切分粒度的判据是什么？

### Q4｜工具路由的规模扩展性与失效点

你的路由是在 40 个工具加 1000 个干扰描述下测的，而且和基线打成平手。如果工具规模是几千个、描述由不同部门各自撰写、还大量存在近义工具，你那个四段漏斗哪一段会最先失效？你会怎么改检索与收敛策略？

### Q5｜电气/机械原理图的 RAG

你现在的知识库只支持 UTF-8 TXT/Markdown。电气原理图和机械装配图是图像加符号加拓扑关系，你要怎么构建这个知识库？向量化的基本单位是什么——整张图、图里的元件、还是子图？图纸之间的跨图引用（比如某个回路引用了另一张图的端子）你打算怎么表达和召回？

### Q6｜时序分析小模型的封装与调用契约

JD 要求封装调用时序数据分析小模型。你的项目里模型调用是怎么封装的——推理超时、模型返回不可解析、模型版本变更这三种情况分别怎么处理？如果换成你们自己训的时序小模型，你会把它做成 Agent 的一个 Skill，还是做成图里的一个节点？为什么？

### Q7｜Agent 算法库的建设思路

JD 里要建设 Agent 算法库。你认为一个 Agent 算法库应该沉淀什么？是按算法族组织（ReAct / Plan-Execute / Reflection / 多智能体），还是按能力组织（检索 / 规划 / 校验 / 恢复）？复用的粒度怎么定，沉淀到什么程度才算「可复用」而不是「只是抄了一遍代码」？

### Q8｜无幂等接口下的写操作安全

你用 operation_id 加唯一约束加回执对账保证写入幂等。如果这边要调的是一套老的 SCADA 或 PLC 上位机系统，它既不提供幂等接口、也不提供回执查询，接口还只能「发出去就不管」，你怎么办？

### Q9｜评测方法论的严谨性

你说做了预登记和 family 均衡率。为什么这类任务不能用普通 accuracy？聚类 bootstrap 是为了解决什么统计问题？你自己报告里出现「95% 区间包含 0」，这意味着什么——是实验失败，还是别的问题？

### Q10｜幻觉与中间结论错误的拦截

Agent 在中间步骤给出一个看起来合理但实际错误的结论（比如算错了退款金额、或把某条政策理解反了），你的系统靠什么拦住它？如果拦住了，你会怎么把这次拦截记录下来、并且不让它下次再犯？

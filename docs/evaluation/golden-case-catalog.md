# 黄金集候选用例规格：80 条

2026-10-09；状态：**人工可审查的设计规格，未生成 fixture、未执行评测**。正式黄金集须补充机器可执行初始化、对话、oracle 与来源审查，要求见 [评测协议](benchmark-protocol.md)。这些是项目自定义 Mock 业务规则，不能当现实商户政策或法律解释。

## 共用业务规则与种子约定

每条使用独立数据库快照。租户 T1 有客户 C1/C2 与客服 S1、主管 M1；C1 不能读写 C2 的订单。用户确认不能替代超过额度的主管批准。客服可在已确认、政策允许范围内自动退款 ≤5000 分；超过由 M1 审批。审批 10 分钟有效，绑定金额/商品/业务版本/政策版本。所有金额以人民币分保存。

基础订单 U：C1，未发货、地址 X，版本 v1，可改址/取消。订单 D：C1，已签收，商品 a/b 原价 6000/4000 分，整单优惠 1000 分按原价比例分摊；已支付 a=5400、b=3600 分，无已退款。破损商品按当前政策可退其净支付价；退款与同一商品补发互斥。普通退货 7 天内按政策允许，超过时禁止自动承诺。优惠券返还按 policy fixture 定义，不默认模型能猜。

不同用例会覆盖基础参数，实际 JSON fixture 后续要把每个覆盖字段明确写出。用例输入以下为示意中文任务；最终需冻结完整用户脚本、动态模拟器规则、工具目录和 oracle。日期使用虚拟业务时钟，事件按“读后/提交前”等确定触发点注入，避免测试依赖真实日历/随机 sleep。

## 下一步转为正式黄金集

为每条生成 JSON fixture、可控制时钟/事件、模型可见任务、隐藏oracle和禁止项；做 fixture/schema 与 oracle 自检；用户/第二审查者确认业务规则；按场景family分割并冻结hash。工具规模/攻击/故障专项需扩充独立样本，不能将本表80条简单复制100次宣称样本充分。

本目录保证业务、核心模块、负例与恢复链路都有具体可审查验收对象。它目前不证明通过率，也不证明已经交付≥50条可运行的黄金测试。

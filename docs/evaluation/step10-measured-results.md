## 解释与公平性

计划确认共1110单元（P/B2/A-plan，74例×5）：CP001–036是预登记复杂主指标；CP001–056是全部新组合；CP057–074是18个已知边界回归，单独披露。全部新组合P259/280、B2216/280，family差+5.82pp，区间[−2.04,+14.80]pp。已知回归的提升不能替代新复杂主指标，也不能充当独立盲测。

工具路由共900单元：50/200/1000目录分别50例×3次×两组。50目录P149/150、R-hybrid150/150；200与1000两组均150/150。使用40个真实商家工具及960个固定版本Gorilla公开描述；两组同样排除3个写工具。外部公开描述只作为候选干扰，不执行第三方API；不是1000个真实电商工具的端到端验收，也不是官方BFCL成绩。在1000目录P输入283246 Token、R-hybrid191260，P中位约4.10秒、基线3.37秒；本实验不能宣称路由准确率、成本或延迟领先。

恢复共348单元：48种可恢复、8种永久故障、2种无故障对照，每组3次。故障由外部控制器修改真实MCP/模拟账本边界；丢失写响应是在退款已提交之后丢弃返回，检查receipt和账务恰好一次。过期观察使用过期envelope时间戳，不是实际等待TTL。永久故障两组24/24安全停止，无故障两组6/6正常完成。原始来源和外生修改日志保留；评分before参考包含控制器修改，不等于最初注入前快照。

恢复分组必须依据冻结的`recoverable`和`fault`语义字段。最初派生报告误按数字区间推断分组，已保留为`step10-analysis-recovery-initial-grouping-error.json`；当前报告按48/8/2语义分组校正，原始轨迹、计分结果、分母没有改动，并加入逆序数据回归测试。RC049–050是无故障，RC051–058是过期观察，不能按编号猜测类别。

各组均使用同一网关模型ID和允许的provider策略，但网关实际供应商分布不同。原始返回的serving_provider与费用均保留，不能把成本差完全归因于算法。主计划P累计API报告费用0.126204135、B20.161355144、A-plan0.224947684；路由P0.140676933、R-hybrid0.033851238；恢复P0.038865872、A-reflect0.030906696（网关cost字段，非已核对账单，不含百炼费用）。主计划P/B2各1次请求缺少usage，路由P1次缺少usage，失败保留并标记，不以0 Token冒充完整计费。

自动评估检查结构、调用参数、当前证据、业务副作用、审批、终态和账务约束。三组已完成数据未检测到自动oracle定义的越权资金副作用；这不证明所有攻击安全。数据没有外部独立人工盲审，最终沟通质量也未作独立人工打分。结果支持上述有限模拟业务范围，不支持“超过Agentforce”“行业顶尖”或跨故障域高可用的市场结论。

## 长会话版本与计费口径

V1的300单元完整保留：P81/150、M-vector48/150；指代题分别51/120、18/120，明确订单对照两组30/30。P有68次WAITING_USER和1次HANDOFF，M-vector有87次WAITING_USER和2次HANDOFF；终态SUCCEEDED但绑定错误也判失败。family均衡率分别47.73%和22.73%，差值+25pp不能掩盖P整体54%的绝对质量不足。

V1全部到达的API已报告聊天输入为P424178、M-vector1201687 Token，表面降低64.70%；分别1/2次聊天请求缺usage，因此首次登记的完整联合Token目标未通过。两组均正确且全部聊天请求有usage的44个配对，输入分别135632/355456，降低61.84%，仅作为次要分析。费用为API报告cost P0.041297327、M-vector0.088810483，不是已核对账单；M-vector有1323次含离线历史准备的检索请求，已完成单元累计准备5829.48秒，P准备75.34秒。失败准备的部分百炼费用缺记录，不能将聊天Token下降等同于总费用下降。

V1修复后在首次新推理前登记V2（新60题、360单元、v4冻结源码）；独立浏览器又暴露共同属性query被改写的问题，v5只加强逐字提取提示，另登记新的V3（新60题、360单元、最终v5源码）。二者使用预登记的条件Token指标：同一case×trial两组均正确、全部聊天请求有usage，至少30个配对、降低≥25%；同时披露全部到达的Token、缺usage和费用。这个条件指标不能冒充原V1的完整联合计费指标。

离线准备HTTP400先停止，保存已评分前缀散列，并以同一请求体做一次诊断；200后仅恢复未评分单元。400原始错误体未留存，不猜测其原因。V2续跑控制进程中断后保留225个评分单元，复核相同失败请求返回200，再续跑；一次排障读取了日志尾部，未据此修改应用、评分、数据或挑选样本。所有版本及失败均交付，不能仅报告较高的一次。

### 已完成的 V2（v4 源码）

新60题×两组×3trial的360单元全部完成。P162/180（90.00%），M-vector72/180（40.00%）；family均衡率分别88.46%/30.77%，差57.69pp，95%区间[35.90,76.92]pp。达到V2登记的差值、正效应、绝对成功率及条件Token联合门槛，但只是这份有限数据的成绩。

两组均正确且所有聊天请求有完整usage的70个配对，占180对的38.89%；输入P197342/M-vector557814 Token，降低64.62%，缺usage排除0对。全部到达已报告输入P568382/M-vector1556720，聊天请求208/197，缺usage均0；API报告cost分别0.0529045615/0.0984383262，不含百炼费用，也不是已核对账单。P服务供应商为Wafer182、Relace24、Morph2次，基线为Wafer192、Relace5次；供应商差异保留，不能把费用变化全部归因于机制。

P的180次终态均为SUCCEEDED，但18次未满足完整隐藏证据约束，依然判失败。12次遗漏承运公司，其余包括物流/订单状态/脱敏地址证据缺失或作用域错误（一个任务可能有多个失败字段）；不能将终态当作正确率。基线有51次WAITING_USER，另有已完成但证据错误的任务。两组本数据均未检测到oracle定义的资金安全失败，不能扩展为未知攻击安全结论。

已完成单元的离线准备合计P74.04秒、M-vector15529.92秒，检索请求分别52/1720；失败准备的额外部分用量未完整归账。准备总秒数是各单元之和，既不是独占墙钟时长，也不是Agent活动延迟。完整结果为`artifacts/benchmarks/step10-analysis-memory-v2.json`，原始轨迹和恢复审计不改动。

确定性回归另外复现了部分投影匹配、优惠券使用门槛和已知投影遗漏守护问题。v6候选只补齐发布契约与解析覆盖守护；当前v5/V3继续原协议完成。后续V4以新的60题作主指标，另4条已知承运回归单独计分；登记见[新版本协议](step10-memory-v4-preregistration.md)。

## 复现

```powershell
uv run --project backend --frozen python scripts/benchmark.py reproduce --manifest artifacts/benchmarks/step10-openrouter-confirmation-v1/source-manifest.json --from-snapshot --check-only
uv run --project backend --frozen python scripts/analyze_step10.py --suite plans
uv run --project backend --frozen python scripts/analyze_step10.py --suite routing
uv run --project backend --frozen python scripts/analyze_step10.py --suite recovery
```

去掉check-only会用冻结源码、数据、日程重新进行真实计费推理，输出至新的实验目录；不可要求云端随机输出逐字相同。长会话的离线历史向量准备出现ReadTimeout时，仅恢复尚未计分的单元，已计分单元不重跑，resume日志和初始中断均保存。未完成离线准备中的部分供应商用量无法完整归账，需要另行对账，不纳入聊天输入Token降低指标。

# Step10 V6 四项深化技术最终量化复核

复核日期：2026-10-11。七项正式冻结实验共 3762 个 schedule 单元，V3 与 V4 按原 schedule 补齐，已评分记录全部保留。本文的最终记忆技术指标采用 V4 新题主集；V3 和旧版本作为单独版本报告，不与 V4 合并。

所有主差值按 family 均衡率计算，95% 区间为 family 配对聚类 bootstrap（4000 次、seed 10001）。同一场景的重复 trial 不是新增独立场景。冻结模型为 OpenRouter `deepseek/deepseek-v4.1-flash`，temperature=0.3、reasoning=false，仍按登记的 provider 白名单与 fallback 执行。

## 失败与安全边界

- 规划主集：P 有 21 个严格失败单元（11 HANDOFF、10 PARTIAL），B2 有 63 个。B2 的高频失败检查包括 HANDOFF 56 次、产品规格字段 54 次、库存字段 55 次、缺失/错误效果检查 114 次；这些检查可能落在同一单元，次数不可相加成失败任务数。P 的失败主要在订单/物流状态和证据完整性。
- 路由 1000 项目录主集两组质量检查均为 150/150；这不证明 1000 个真实电商 API 的覆盖。完整 900 单元中 P 有 1 次 HTTP 失败及 1 次 usage/费用缺失，已保留。
- 记忆 V4 新题主集：M-vector 118 个严格失败单元，其中 51 次 WAITING_USER；缺失/错误检查集中在运费字段（24）、保修范围（12）、订单折扣（12）、优惠券门槛（12）、库存（12）和客服时间（12），检查可能重叠。P 为 180/180。另 24 个已知承运遗漏回归不进入主集：P 12/12，M-vector 9/12；M-vector 的 3 个失败含承运信息与预计送达字段遗漏，单列披露。
- 失败恢复主指标只含可恢复的 48 类×3。基线 144 单元中有 48 FAILED 与 48 PARTIAL；证据错误检查包括物流状态 96 次、退款金额 24 次、资格判断 24 次（检查可能重叠）。永久故障的安全停止另报：两组均 24/24 PARTIAL；无故障对照两组均 6/6 SUCCEEDED。没有把这些控制组混入可恢复主分母。
- V3 新题主集为 P 180/180、M-vector 70/180；family 均衡差 +70.51pp，95% CI [+50.64,+88.46]pp，13 families。V3 的 M-vector 有 43 个 WAITING_USER；另有库存、支付方式、发票、物流等证据失败。V3 全到达 usage/费用和 V2 历史版本详见[原始汇总](step10-measured-results.md)及[`V3 分析 JSON`](../../artifacts/benchmarks/step10-analysis-memory-final-v3.json)。V3 不与 V4 合并。
- 浏览器验收中，正确订单范围的两条只读查询通过。另一次未给订单号的“客服时间及优惠券门槛”请求 HANDOFF 并创建一个模拟工单；已列入独立失败证据，不算通过。该尝试没有商家或财务写操作。

所有 strict success 由已冻结的结果 oracle 判断，包含状态、订单作用域、当前证据与回执等约束；终态 SUCCEEDED 本身不等于成功。新题使用公开缺陷术语或相邻领域构造，未做独立人工盲审。结果适用于这些冻结模拟场景，不能外推为所有用户、真实商家或任意攻击的可靠性承诺。

## 冻结恢复、费用缺失与监控披露

V3 从 108 条保留结果继续，四段恢复计数为 108→180→275→309→360；完整 360 行分析的 `raw_results_sha256` 已记录。准备阶段有 6 次 ReadTimeout 重试、3 次 HTTP400终止；对三个完全相同请求体各做一次隔离精确探针，均 SHA-256 匹配并返回 200，合计报告 15,416 Token。失败准备调用 usage/cost 未报告，不计入 chat usage。V3 联合登记指标均达到，但没有独立盲审。

V4 从暂停前 14 条恢复，暂停时 `case-results.jsonl`、`provider-calls.jsonl`、`offline-retry-events.jsonl` 三个前缀的字节数与 SHA-256 均先行核对。审计记录 14→154 的 HTTP400 中断，以及恢复参数下 154→384 的成功补齐。一次精确探针预检因诊断脚本错误枚举已删除/过期会话，在 provider 请求发出前以 404 结束；已保存 [`未发出请求的预检记录`](../../artifacts/benchmarks/step10-memory-final-v4/preflight-probe-v4-not-sent.json)。修正的只是诊断脚本候选筛选；随后一次精确探针匹配原请求 SHA-256、HTTP 200、报告 5156 Token，失败到探针约 4 分钟。V4 另记录两次 ReadTimeout 重试。V4 冻结应用、评分器、模型、数据及 schedule 未改。

两项监控披露均如实保存：V3 进度检查曾读到 8 行含 `strict_success` 的子进程日志，此后没有质量分析、挑样或评分变更（[`V3披露`](../../artifacts/benchmarks/step10-memory-final-v3/monitoring-disclosure-20261010.json)）；V6 两小时窗口的一次状态轮询曾输出缓冲的逐到达运维行，含状态、工具名、usage、workflow 标识及 pass flag，不含消息文本，之后只用聚合计数监控（[`V6披露`](../../artifacts/step10/live-soak-final-v6-resumed-20261010/monitoring-disclosure.json)）。

## 解释范围

完整 3762 单元分别为规划 1110、工具路由 900、记忆 V1 300、失败恢复 348、记忆 V2 360、V3 360、V4 384。旧版完整数据、V1/V2 的详细成本与 Token 计算、分组修正和复现命令仍保留在[历史测量报告](step10-measured-results.md)。API 返回的费用不是账单对账；offline embedding 费用不完整；provider mix 有差异；失败检查存在重叠；多 trial 是同场景重复测量；V3/V4 与全新场景都未独立盲审。这些限制和本次未达标项一并交付。

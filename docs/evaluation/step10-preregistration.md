2026-10-10，首次 CP 推理前登记。用户已授权连续完成步骤 9、10。本登记是比较方法，目标值不代表已达成。保留所有失败、开发与旧供应商结果。

## 数据和比较

- EC001–060 已用于诊断，作为开发集。旧 DeepSeek 官方模型 2100 个任务和 208 个持续运行任务独立归档。
- OpenRouter 开发 v1：60×2，P 与 B2，共120。原用量汇总未把 OpenRouter 归为聊天供应商，原始 provider-calls 有真实 usage；新增 usage-corrected-results 从原始记录派生，不改原文件、质量结果或重跑推理。冻结 manifest 中旧 temperature 字段为0，实际请求为0.3；该批只作开发诊断。
- CP001–056：56条新编排任务，其中36条复杂任务。CP057–074：18条已知边界回归，单独标识，不当作全新样本。新数据在首次 CP 推理前冻结。未独立人工盲审，不使用“人工黄金集已验收”措辞。
- 主确认运行：P、B2、A-plan，每条5次，随机交错 seed=10001、并发4，共1110个任务。主指标是新复杂 CP001–036 的任务成功率，按真实场景族配对聚类 bootstrap；整体新题与边界回归分别附报。
- B2 是强检索 ReAct：真实 BM25+dense+RRF+qwen3-rerank Top8、可 search_tools 动态换批、原生多工具调用、完整工具消息配对与最近8组窗口。共享商家 Gateway、确认/审批、预算、模型及供应商限制。B0全目录与B1纯dense旧结果仍保留，不用弱基线代替 B2。
- A-plan 仅替换编译 DAG 为模型线性步骤；其他能力保留。新的业务投影拆分、精确实体约束和槽位校验属于 P 的可验证规划/路由实现，不从基线删除通用授权保护。

## 四项目标与证据边界

| 技术 | 指标和目标 | 实验 |
|---|---|---|
| 可验证复杂计划 | 完整目标/证据/副作用正确率，相对B2提升≥8百分点 | 新复杂任务配对，失败包括遗漏、错误绑定、业务效果、预算超限与传输错误 |
| 大规模工具路由 | 工具+所有参数联合正确率，相对强检索提升≥5百分点 | 生产40工具闭环；另做50/200/1000真实公开工具描述混合目录的只读路由组件实验，不能称1000真实商家接口已接入 |
| 时效记忆/上下文 | 长会话正确率+8百分点且实际prompt_tokens减少≥25% | 同一会话历史、相同问题和当前商家状态；最近窗口+向量历史基线对比结构化实体账本/引用卸载；人工审批不继承，过期事实必须新读 |
| 证据反思/恢复 | 故障任务正确恢复率+15百分点 | 相同故障控制器事件序列，固定重试基线与证据校验/刷新/恢复方案配对；必须包含当前状态变化、过期、瞬时故障及写回执对账，安全停止另报 |

一次试验的目标达到不代表行业顶尖，也不直接证明超过 Agentforce/Dify：未对封闭商业系统执行同集测试。至少3项有效改进是交付成果门；不以篡改任务、删除失败、换分母或多次看确认集调参实现。

## 统计、预算和可复现

- 同一模型 deepseek/deepseek-v4.1-flash，OpenRouter，temperature=0.3、reasoning.enabled=false，用户供应商only名单、allow_fallbacks/require_parameters=true。实际 serving_provider、usage/cache/reasoning_tokens/cost 保留；fallback可能使实际供应商不同，报告分布与该限制。输出预算按意图/工具/批调用设定，同类步骤各组相同；用户512示例不是所有复杂规划的统一上限。
- 每个任务12次模型请求、20000模型Token、30逻辑工具调用、180秒活动时间；人工等待另计。边界检查允许验证/发布刚消耗完预算的最后结果，但禁止再发起超预算请求。MCP握手/重试物理网络次数另报，不混称逻辑工具数。
- 比较同case×trial；重复推理不是独立新业务样本。族内平均后聚类 bootstrap 4000次，固定seed。达到百分点目标与置信区间是否支持正效应分别列示，安全/审批/费用/延迟为护栏。
- 运行挂载冻结源码而非活动工作区；真实商家模拟 MCP 使用不可变容器镜像，无隐藏oracle挂载。独立评测数据库、Redis9，客户/政策固定快照。正式数据不写 episodic/AWM 训练；记忆专项使用独立预置历史，不从测评结果学习。
- 时间上界估算为UTF8字节数；输入Token收益仅用供应商实际prompt_tokens。usage缺失、错误或重试不默默填0，不剔除失败。API返回cost称“供应商报告费用”，不称已经核对的账单。
- 主确认集只运行预登记批次；若需要修复，原批保留为未通过，改用新的版本化确认集并公开变更理由。开发诊断可在EC集迭代。

## 可用性/交付

容量测试直连localhost，trust_env=false，避开Windows系统代理；旧代理路径502保留。新Nginx使用Docker动态DNS，验证API重建后恢复。控制API负载与真实模型吞吐分别报告。单机Compose并非跨节点HA；数据备份/恢复、依赖故障和受控降级用实际演练验收，多可用区HA为有配置要求的部署升级项。

首次推理前校验补记：140条新题投影预期逐项匹配权威投影，24个请求写意图使用实际模拟客户确认枚举 confirm_and_approve；物流节点预期校正为商家交运。主确认与直连控制API压力测试可能在同一宿主机重叠，因此质量对照随机交错，延迟结果明确包含负载干扰，不作独立空载吞吐推断。

专项首次推理前登记：MC001–050 每组3次 P/M-vector 共300，seed11001，并发1；向量基线最近5轮+真实embedding Top8去重，最多13个完整历史记录，真实prompt_tokens统计；历史由固定模拟快照预置，不称全部历史轮均来自真实LLM。RC001–058 每组3次 P/A-reflect 共348，seed13001，并发1；主恢复分母仅48条可恢复故障，持续不可用8条与无故障2条另报安全停止。工具路由TR001–050 ×50/200/1000目录×两组×3次共900，seed12001；强基线BM25+dense+RRF+qwen3-rerank Top8，原生多调用，允许search_tools最多3轮；P复用生产TaskSpec与受控投影契约，不用oracle指导选择；外部960描述来自Gorilla固定commit及Apache2许可证，均不执行。三组新集没有独立人工盲审。

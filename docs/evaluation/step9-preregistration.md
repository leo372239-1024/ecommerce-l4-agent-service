## 冻结与样本

- 数据：[step9-dataset.json](step9-dataset.json)，v4共60条，SHA256 `f49a39ffb7e065974059198582260cfb2d2dab4ee035cb005489e687d5feec5b`。金额为分；本轮独立商家政策阈值5000分、退货期限7天。审批期限沿用实际实现15分钟，原GC设计的10分钟未作为已实现事实。
- 每条5次，B0/B1/P/A-plan/A-route/A-memory/A-reflect共2100个episode；seed=901，随机交错、并发4。按用户2026-10-10的新指令，对照均使用`https://api.deepseek.com`、`deepseek-flash`、temperature=0、thinking disabled；候选目录40个真实工具，没有复制假工具补足50/200/1000档。
- 每个episode新建独立订单实体与业务状态，模型只收到用户任务和经授权工具结果。隐藏oracle不进入模型上下文。业务库为`agent_benchmark_step9`，MCP/API/Worker使用独立服务，Redis DB9；现有演示业务库保留。复用PG/ES宿主及Docker网络，**不是物理隔离的新机器或HA环境**。
- 所有模型请求真实发往供应商，关闭评测器推理缓存；请求状态、返回model与原始usage分账归档。不可假定temperature=0导致完全确定。供应商不可变模型revision不可获得，金额费用需账单/确认价格，不能由Token自行换算。
- 源文件逐文件hash、lock hash、镜像ID/digest与实际资源写入source-manifest。当前工作树没有既有提交，不能伪造commit。相同实验名仅允许相同源码、数据和参数恢复，重跑必须使用新实验名。
- `pipeline*`与`adapter-check`是编写评测适配器期间的工程冒烟，包含工具消息协议和JSON断点恢复修复；不进入本轮成绩，不声称它们与EC主集相互独立。生产Agent超参数不根据主运行结果调优；主运行期间不修模型行为后挑选重测。
- v1开始后发现脚本客户的批准范围过宽，会确认Agent新增的写意图。该批次作废，原始结果和原因保留在`step9-main`；v2明确客户只确认原任务中允许的订单/动作，其他提案拒绝。此修订修改用户模拟器，不根据P/B1得分选择修题。
- 2026-10-10运行前修订：v2在完成283条后，下一条任务初始化订单的COMMIT超过控制器5秒超时，Agent尚未启动；原始数据、日志与interruption保留，批次作废。v3仅为初始化/终态取证使用30秒独立连接，初始化允许最多3次同实体幂等重试并核对全部字段；Agent业务连接仍为5秒，执行失败不选择重测。初始化时间单列。并发统一改4，全部七组从头重跑，主证据为`step9-main-v3`。
- v3进一步限定证据所属业务工具，避免同名eligible来自保修/地址接口却被当作退货资格；允许报价、订单快照等有明确等价映射的合法来源。任务文字、订单状态与客户批准脚本不变。HTTP运输失败也归档，不再只记录已返回的响应；所有修订在v3首条执行前冻结。
- 用户切换模型时停止v3，保留841条GLM部分结果，标记interrupted_user_model_change，不合并入新实验。v4在新批次前修正EC011：共同安全过滤器将phone进一步遮蔽为`[REDACTED]`，oracle接受实际安全输出；各组统一重跑。主证据目录为`step9-deepseek-main`。历史GLM结果与容量测试均注明模型/环境，不冒充DeepSeek完整比较。
- DeepSeek模型列表、非思考强制工具调用与工具续接均真实验证。使用相同non-thinking模式，避免默认high思考耗尽原有短输出预算或要求旧ReAct消息补传reasoning_content。供应商前缀缓存不可由本轮手动关闭，命中/未命中Token按返回usage原样记录；评测器不回放缓存响应。相关参数与源码在首条新主任务前冻结。
- DeepSeek冒烟发现普通ReAct适配器只接受单工具响应，现改为checkpoint中保存批量调用并顺序执行、保留完整assistant/tool组，审批后继续剩余调用；实际API未执行parallel_tool_calls=false，因此不依赖该参数。写工具描述明确它先发起确认提案；缺少必需订单/政策事实返回工具错误，允许同预算下检索修复。这是供应商/网关协议修订，不把未兼容适配器的失败当作基线模型能力；早期DeepSeek冒烟不进入主结果。

## 对照定义

| 组 | 实际实现 | 限制 |
|---|---|---|
| B0 | LangGraph ReAct，完整40工具schema，正常assistant/tool配对，固定窗口与预算 | 模型最终文本不能代替业务终态；多轮重复传schema也计成本 |
| B1 | ReAct、dense Top8、按需search_tools重新检索、正常窗口；相同底层身份/归属/网关/幂等/审批 | 本轮无跨会话向量记忆，称**短任务B1**，不是完整长会话强基线 |
| P | 当前完整Harness | 评测分区不学习，也不召回历史记忆/AWM |
| A-plan | P把编译DAG换成模型线性动作序列，去掉整体DAG验证；其余意图、路由、上下文、核验、反思、网关相同 | 仍需基础参数类型与身份校验，否则违反共同安全控制 |
| A-route | P把混合召回/精排换为dense Top6 | 精确效果单候选路径各组相同；目录仅40 |
| A-memory | P不注入Context Builder包 | **只衡量上下文包**，不能据此声称长期记忆/AWM收益；两组均不召回历史记忆 |
| A-reflect | P只对暂态只读错误重试一次，不做反馈驱动修复 | 主EC集未包含动态故障，主集无差异不能证明恢复等价 |

B0/B1同样通过受控意图适配器获得服务端operation_id/hash，客户确认和主管审批调用相同审批处理器；不让模型自己生成业务授权。脚本客户在提案到达后确认，超额度再由真实主管角色批准。主实验直接调用与REST共用的审批业务处理器，独立REST/会话/CSRF/CAS/重启链路由恢复套件核验。

主任务由控制器直接RunStore.create，未经过REST输入admit_message；用于保持Harness比较与把指定攻击输入实际交给模型，不能据此声称端到端输入防线/产品接管率。所有组仍调用相同身份、归属、租约、提案审批和业务账本控制。登记的56个family仍有共享fixture/查询模板，bootstrap只描述本工程集，不代表客户总体分布。

## 评分与统计

机器通过要求：允许的终态、必需字段、订单绑定、准确副作用次数/金额、账本余额/实体版本、客户确认/主管批准、禁止的跨目标字段与归属检查全部满足。多个合法工具顺序都可通过。拒绝/转人工只有预先允许的任务才算合法闭环；把退款要求只回答报价会失败。最终自然语言沟通rubric尚待人工评审，**机器通过率不是完整人工审查后的strict task success**。

同case/trial配对；按family做等权cluster bootstrap（4000次），报告其估计口径与95%区间；总体episode率另列。首次trial的Wilson区间仅是描述性参考，不消除family相关性。pass^5使用`C(s,5)/C(n,5)`，不能解释成5次至少1次成功。探索性多组比较不作确认性显著结论，也不声称满足预注册三项深化收益。

自动评分缺失的关键范围：开放式回答全部claim/引用的人工裁决、跨会话纠正/删除/AWM收益、动态用户模拟、1000真实工具目录、独立隐藏安全/故障场景集。保留这些缺口作为验收门失败原因，不能以单元测试或重复措辞补足样本。

## 压力、持续运行与故障

- 控制API `/runs?limit=20`，预热20秒，按1/10/50/100并发计划各600秒；全局错误率>1%或最近100请求P95>2秒即停止并不再升档。早停档保留数据。请求不调用模型，不将其RPS标成Agent RPS。容量初次驱动仅采样阶段资源；后续驱动新增每10秒采样和API/PG内存90%停止规则，两版本结果须区分。
- SSE 10/50/100/200连接，包含10%慢读客户端、持久游标重连、序号检查和他人流404；有错误即停止升档。本轮是QUEUED观察流，不代表200个同时推理Agent或高事件吞吐。
- 主运行持续至少7200秒；若2100个比较episode提前结束，则继续真实P只读任务，按30秒间隔到达（执行超过30秒则立即接续），单独存入`soak/`，不增加黄金样本量或比较成绩。资源随时间归档。这是持续定时业务负载，非满载两小时，也不是仅挂空计时器；到达节奏在新DeepSeek主运行前固定以控制额外推理支出。
- 故障套件在主实验结束后串行执行，复用既有真实模型/HITL/写响应丢失/提交后kill Worker/取消后账务保真的验收，重定向到独立步骤9服务；保留故障终态与操作唯一性证据。200个MCP边界探针是40工具×5攻击类型、强相关，另有权限/政策/批准撤销检查，不能称200个独立模型注入场景，也不能用0/200证明普遍安全。
